# H-Beauty — 48 independent makeup portrait production brief

**Release state: NOT COMPLETE.** No completed images are certified by this document. It defines the shot roster and mandatory evidence for 48 separate images of the exact user-approved model.

## Meaning of “48 separately photographed”

A **photograph** requires an actual independent photographic exposure with the specified makeup applied to the model. A synthetic AI makeup edit may look photographic but must be recorded and labeled **AI-edited portrait**, never an actual salon treatment photograph. The two asset types are not interchangeable in advertising or before/after claims.

The source image (`public/makeup/model-reference.webp`, 480×640) is only an identity anchor, NOT an acceptable substitute for the 48 final photographs.

## Quality / identity controls

- Use the same consenting model for all 48 real photographs. Retain original face shape, nose, eye spacing, natural dimples, lip proportions, age, and skin texture. No digital identity substitution or face reshaping.
- Each final must be an **independently distinct portrait** with visible makeup actually matching its name. Mere recoloring a palette label, cropping the same photo differently, or duplicating pixels is NOT a pass.
- Export a genuine 3:4 portrait at at least 900×1200 pixels, preferably 1500×2000; accurate white balance, neutral off-white/blush background, even beauty lighting, natural skin texture, no heavy smoothing.
- Keep facial features clearly visible; avoid obstructive hair, aggressive glamour filters, invented jewellery, text, stickers or overlays.
- Record per-look origin, shot identifier/reference, photographer/editor, authorization for public use, and human-reviewed identity match. The app must distinguish real photographs from simulated images.
- Save as `public/makeup/results/<look-id>.webp` and record evidence in `.makeup-approvals.local.json (private, Git-ignored)`. Approval flags must be completed only by a real responsible reviewer, not generated by scripts.

## Release gate

Run `npm run verify:makeup-48` after uploading the files and supplying the real human-review provenance manifest. Approval records belong in a private untracked `.makeup-approvals.local.json`, or set `MAKEUP_APPROVALS_PATH` to an external protected file — never put model consent evidence in `public/` or commit it to this public repository.

Private manifest shape for **each** of the 48 images (illustrative only; do not set approval flags true until verified):

```json
{
  "looks": {
    "mk-natural-01": {
      "assetSha256": "<actual SHA-256 of mk-natural-01.webp>",
      "provenance": "photograph",
      "captureId": "<unique camera frame or shoot identifier>",
      "makeupApplied": false,
      "identityApproved": false,
      "publishApproved": false
    }
  }
}
```

Once all 48 images pass, build the final **offline** app with `npm run build:makeup-final`. That command enforces the image gate and pre-caches all 48 individual local WebP files in the service worker. The ordinary `npm run build` remains an editorial concept preview with a shared unretouched reference; it must not be marketed as 48 performed looks. The script checks all 48 file paths, duplicate byte hashes, the original-photo hash, basic WebP validity and minimum extended-WebP dimensions, independently documented capture IDs, actual makeup-application attestations, and SHA-matched identity/publication approvals. The current requirement permits only real photographs, not AI edits. This is not a forensic identity detector or a substitute for review.

Until those assets actually exist and pass both automated and visual review, the application must remain on its draft branch with its current **concept** labeling. Do not claim 48 independently photographed results, and do not deploy marketing pages that imply these were completed salon treatments.
